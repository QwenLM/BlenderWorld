# BlenderWorld submission format

A submission is **one ZIP per task**, produced by any model or generation harness.
Evaluation requires the dataset, the submission ZIP, and the configured evaluator.

## What the model must deliver

Use Blender **4.2.10** and save the primary editable project as **`final.blend`**.
Keep all dependencies inside the output directory, using relative paths or packed
textures. Include every image, video, or other export requested by the task.

```text
bw_0001.zip
  final.blend                 # required: primary project at the ZIP root
  textures/                   # optional: dependencies used by the project
    wood.png
  outputs/                    # optional: images, videos, mesh exports, etc.
    render.png
    animation.mp4
  submission.json             # optional: generated by bw pack-submission
```

`textures/` and `outputs/` are recommended folder names; other relative paths are
accepted. Extra `.blend` files may serve as linked libraries, but evaluation opens
`final.blend` as the primary project. A ZIP containing only `final.blend` is valid
when the task requires no other exports or external assets.

Do not add a wrapping directory such as `bw_0001/final.blend`. Package the output
directory's **contents**. Include deliverables only: keep inputs, evaluation
rubrics, transcripts, configuration files, and credentials outside that directory.

The generation runtime pins Node.js **22.17.0**, Codex CLI **0.147.0**, and Claude
Code **2.1.220** when those tools are used. Other model harnesses can produce the
same format. Packaging does not convert projects between Blender versions or
verify which model generated them.

## Create a ZIP

Recommended: collect the model's files in any output directory, then run:

```bash
bw pack-submission --source model-output --task-id bw_0001 \
  --output submissions/bw_0001.zip
```

The packer checks the required project, preserves relative paths, and generates
`submission.json` with the task ID and SHA-256 hashes of every delivered file. It
refuses to overwrite an existing ZIP. An existing standard ZIP is also accepted
as `--source` for adding or verifying its manifest.

A normal ZIP tool works too; no BlenderWorld-specific metadata is required:

```bash
mkdir -p submissions
(cd model-output && zip -r ../submissions/bw_0001.zip .)
```

For tools implementing the optional manifest, the schema is:

```json
{
  "format": "blenderworld-submission-v1",
  "task_id": "bw_0001",
  "files": {
    "final.blend": "<64 lowercase hexadecimal SHA-256 characters>",
    "textures/wood.png": "<64 lowercase hexadecimal SHA-256 characters>"
  }
}
```

The `files` map must list every regular file in the ZIP except `submission.json`
itself, using paths relative to the ZIP root. When present, the manifest's task ID
must match the task being evaluated and every checksum must match on extraction.
The manifest is bookkeeping and is not scoring evidence.

## Evaluate

Install the package and configure the tools and model endpoints described in
[the evaluation guide](evaluation.md). Then:

```bash
# Check one submission without Blender or model calls.
bw evaluate --dataset data/BlenderWorld --submission submissions/bw_0001.zip \
  --output runs/one --dry-run

# Score the same submission using the recorded plan.
bw evaluate --dataset data/BlenderWorld --submission submissions/bw_0001.zip \
  --output runs/one --resume

# Score all tasks in the dataset.
bw evaluate --dataset data/BlenderWorld --submissions submissions --output runs/full
```

The filename selects the task for a single ZIP. Use `--task-id bw_0001` if the ZIP
has another filename. Batch evaluation reads `<task_id>.zip` for each selected
task; repeat `--task-id` to evaluate a subset. Use the matching dataset and public
task IDs (`bw_0001`–`bw_0223`).

Dry-run checks the directory layout and task mapping. Full evaluation verifies
checksums while extracting into a separate workspace, checks runtime versions,
renders evidence, and judges it against the task's rubric. The source ZIP remains
unchanged. Missing or malformed submissions receive zero and remain in the
selected denominator. Evaluator runtime configuration errors abort the run.

ZIPs are limited to 100,000 members and 20 GiB of uncompressed data. Absolute paths,
parent-directory traversal, duplicate names, links, special files, and empty
`final.blend` files are rejected. A valid container layout alone does not guarantee
that Blender can open the project or that the task requirements are met.
